# Demo recording script

The exact click-by-click sequence for the demo-day video. Designed to be ~90 seconds, recorded as two takes (web + iPhone) and spliced.

Companion docs:
- `docs/DEMO_DAY_BRIEF.md`: the ordered P0-P9 build brief from earlier sessions.
- `docs/imessage-agent-runbook.md`: what the iMessage agent actually does and what env vars it needs.
- `docs/prod-env-checklist.md`: env vars to verify in Vercel before recording.

## Recording posture

**Record web and iPhone separately. Splice in editing.** Running both halves in one take requires two devices, two recordings, perfect timing, and a healthy Photon round-trip on whatever wifi you're on. Splicing eliminates three sources of failure for one editing pass.

- **Web side**: live screen recording, 1280x720 minimum, 60fps preferred. macOS QuickTime + Cmd+Shift+5 → Record selected portion.
- **iPhone side**: AirPlay or QuickTime mirror via USB. Record at 60fps so typing reads cleanly.

## Pre-flight (run T-30 minutes before recording)

| Step | Verifies | Action |
|---|---|---|
| 1 | LLM key, Photon adapter, Anthropic round-trip | `node scripts/photon-smoke.mjs` (5 PASS lines required) |
| 2 | Verify card pre-loaded | Sign in to dashboard 5 minutes pre-recording. Confirm `/integrations` shows the verify card in `verified` state for the demo phone. |
| 3 | Bot can text | From the demo phone, text the bot's iMessage number `ping`. Bot should reply within 4s. If not, stop and debug before recording. |
| 4 | Gmail draft path | From the demo phone, text `draft an email to <recipient>@... saying test`. Reply `yes`. Confirm a draft lands in the demo Gmail account. Delete the draft. |
| 5 | Calendar create path | From the demo phone, text `schedule a meeting tomorrow at 3pm about test`. Reply `yes`. Confirm an event lands in the demo Google Calendar. Delete the event. |
| 6 | Browser cleanup | Close all unrelated tabs. Disable browser extensions that may inject UI (1Password, Grammarly). Set browser to incognito + no extensions. |
| 7 | Phone cleanup | DND on. Wifi clean. Battery >50%. iMessage thread cleared down to the demo bot. |

## The 5-step sequence

| # | Surface | Action | Visible result | Voiceover (read aloud) |
|---|---|---|---|---|
| 1 | `/integrations` | Show the iMessage verify card already in `verified` state. Hover the editable prefs (zodiac, location, model). | Verified phone bound, prefs editor visible, Send-test button visible. | "Sign in once. Your phone's on file. Edit prefs from the dashboard or your phone." |
| 2 | iPhone iMessage | Type `what's the weather in Austin` and send. | Bot reply with current Austin forecast within 2-4 seconds. | "Free-form chat backed by Claude Haiku. Five-turn memory across iMessage and the web." |
| 3 | iPhone iMessage | Type `draft an email to <real-recipient> saying running 5 minutes late` and send. | Bot replies: `Draft to <recipient>: running 5 minutes late. Reply YES to confirm or NO to cancel.` | "Approval-first. Nothing irreversible without a tap." |
| 4 | iPhone iMessage | Type `yes` and send. | Bot replies: `Draft saved to your Gmail (id 7d3a02fc). Open Gmail to review and send.` | "YES means YES. Real Gmail draft created." |
| 5 | Web (cmd+tab to Gmail) | Show the new draft sitting in Gmail with the recipient + body intact. | Real recipient, real body, ready to send. Show the Send button without clicking it. | "Receipt's signed. The action is yours to publish." |

Total runtime at human pace: 80-95 seconds.

## Editing rules

- **Cut the typing**: jump-cut from input field empty to input field full. Don't show 30 seconds of someone typing `draft an email to ...`.
- **Cut the typing indicator**: the iMessage bot-typing dots sit for 2-3 seconds. Speed-up 1.5x or trim to 1s.
- **Cut transitions**: no fades, no zooms. Direct cuts only.
- **Subtitle bar at the bottom** with the 5 voiceover lines exactly as written above. Judges remember captions, not voiceovers.
- **Audio**: optional. ElevenLabs-generated voiceover is acceptable per Wave 5 deliverable. Mention upfront that the narration itself is generated by the same AI stack the product uses.

## What to demonstrate vs. cut

| Beat | Show? | Why |
|---|---|---|
| Verify card in `verified` state | yes | Anchors the trust pitch |
| Verify card prefs editor | yes (hover only, don't edit) | Shows the dashboard CRUD without slowing the demo |
| Send-test button | no | Adds nothing to the story; cut |
| Disconnect button | no | Bad smell mid-demo; cut |
| `STOP` keyword | no | Stops the demo literally |
| Multi-model picker | implied via voiceover; don't open the dropdown | Showing the menu eats 5 seconds |
| `/dev/photon` admin panel | only in fallback (see below) | Not user-facing; only for operators |
| The signed receipt UI on `/security` | optional 6th beat if time permits | Strong trust closer; adds 15s. Show the receipt row's `filecoin: <cid>...` link as the final reveal (PR #515 added it). Click and let the public IPFS gateway render the JSON for ~2s before cutting. |

## Fallback if Photon dies during recording

Use the existing `/dev/photon` simulate panel (`app/dev/photon/page.tsx:152-188`). It POSTs a synthetic webhook signed with `PHOTON_WEBHOOK_SECRET` so the dispatch chain runs without involving Spectrum.

What changes:
1. Replace iPhone steps 2-4 with web-side simulate clicks.
2. Operator clicks "Simulate webhook" on `/dev/photon`, types the same text the iPhone would have sent.
3. Synthetic inbound row appears in the recent table within 2-3 seconds with the bot's reply.
4. Show the inbound row's `reply_text` field as the bot reply.

Verbal patch: *"For the recording we ran this against a real iPhone. To show you the round-trip without a phone in your hand, here's the simulator that fires the same webhook our production bot fires."* No apology. The simulator is a feature, not a hack.

## Minimum viable demo if time runs out

Two beats only:

1. iPhone text: `draft an email to mom@... saying I'll be late`.
2. iPhone reply: `yes` -> bot creates the Gmail draft.

That's 25 seconds. Loses weather, loses prefs editor, but keeps the **approval-before-action** message which is the only thing that distinguishes this product from "ChatGPT plus a Gmail tool."

## Things that will burn the recording

- A live LLM round-trip slower than 5 seconds (kills the rhythm). If Anthropic is slow, retry until you get a sub-3s reply, then record.
- A bot reply that includes the user's literal phone number in the rendered text (privacy on camera). The current keyword/intent replies don't, but verify on a dry run.
- A pending action with a stale draft from earlier testing. Run `STOP` then `START` from the demo phone before recording; or curl the cleanup route at `/api/cron/photon-cleanup`.
- An iPhone notification overlay (Slack, etc.) appearing mid-demo. DND.
- A browser autofill suggestion popping up in the Gmail draft step. Use a freshly-cleared form.

## Hard rule

Do not edit any file under `lib/photon/`, `app/api/webhooks/photon/`, `app/api/integrations/imessage/`, or `lib/google/` between now and recording. The 221 photon hermetic specs cover the green path; risk of regression is higher than the marginal benefit of any tweak.

## Generating the voiceover via /api/voice/synth

PR #515 wired the ElevenLabs adapter at `/api/voice/synth`. Use it to generate the narration MP3 instead of a separate ElevenLabs editor:

```bash
# Generate one MP3 per voiceover line. Logged-in admin session required;
# grab the Privy bearer token from devtools (localStorage.token).
TOKEN="$(pbpaste)"   # paste your token first

for i in 1 2 3 4 5; do
  case $i in
    1) TEXT="Sign in once. Your phones on file. Edit prefs from the dashboard or your phone." ;;
    2) TEXT="Free-form chat backed by Claude Haiku. Five-turn memory across iMessage and the web." ;;
    3) TEXT="Approval-first. Nothing irreversible without a tap." ;;
    4) TEXT="YES means YES. Real Gmail draft created." ;;
    5) TEXT="Receipts signed. The action is yours to publish." ;;
  esac
  curl -sS -X POST https://www.operatoruplift.com/api/voice/synth \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"text\":\"$TEXT\"}" \
    -o "voiceover-step-$i.mp3"
done
```

Stitch the five MP3s in your editor of choice with ~0.3s gaps between lines. Total runtime lines up with the 80-95s recording target.

Voice defaults to Rachel (clear narration). To use a different voice, set `ELEVENLABS_VOICE_ID` in Vercel or pass `voice_id` in the POST body.
