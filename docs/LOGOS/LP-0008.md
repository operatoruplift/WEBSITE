# LP-0008: Autonomous AI Module with Wallet, Storage, and Messaging

**Status**: Not entered. Prize text captured; design notes only.
**Prize URL**: https://ns.com/LP-0008.md
**Fit**: 🔥 **Strongest fit of the 7.** Direct overlap with Operator Uplift's architecture.

## Prize summary (from Logos Press)

This prize is for a **Logos Core module that runs an autonomous AI agent with native access to the full Logos stack**: a LEZ wallet, Logos Storage, and Logos Messaging. The agent has its own identity and funds, can communicate with its owner via chat, and can communicate with other agents. The owner deploys the agent on a remote node with a single CLI command and interacts with it from any Logos app instance.

## Why this is the strongest fit

The Arkiv Network School entry (PRs #620-#646) already implements the off-LEZ analogue of this same pattern:

| Capability | Arkiv (shipped) | LP-0008 (proposed) |
|---|---|---|
| Agent has its own identity | Agent entity card on Arkiv Braga | LEZ account + Logos identity |
| Agent has its own funds | Solana devnet x402 invoices | LEZ wallet, native |
| Memory survives operator | `memory-event` entities transferable to user | Logos Storage |
| Owner-to-agent messaging | iMessage + chat (via Photon) | Logos Messaging |
| Single-command deploy | `pnpm arkiv:publish-agents` | `logos deploy ai-module --node <addr>` (target) |
| Verifiable identity | SHA-256 checksum + on-chain entity | LEZ account pubkey |

The Arkiv shipment proves we understand the architecture. LP-0008 is the Logos-native expression of it.

## What we would build

1. A **Logos Core module** (Rust) implementing the agent runtime: lifecycle hooks, message dispatch, scheduled tasks, signed action emission.
2. **LEZ wallet integration**: agent signs its own outbound actions; the owner funds the wallet at deploy time.
3. **Logos Storage integration**: agent reads/writes its memory + audit log to Logos Storage instead of a centralized database.
4. **Logos Messaging integration**: owner sends instructions, agent replies, agent talks to other agents via Logos Messaging.
5. **CLI entry point**: `logos ai-module deploy --owner <pubkey> --node <addr>` produces a running agent on a remote Logos node.
6. **Reference scenario**: a "calendar assistant" agent that schedules meetings on the owner's behalf, with every action signed by the agent's LEZ wallet and logged to Logos Storage. This is a direct port of `/agents/calendar.json` from Operator Uplift.

## Why we are well-positioned

- Operator Uplift has been running a production version of this architecture for months: per-action approval, ed25519 signed receipts, agent identity manifests, multi-channel transport.
- The Arkiv entry already documents the agent-identity + transferable-memory pattern.
- We have a 7-piece agent JSON manifest format (`lib/agent-registration/index.ts`) that ports cleanly to a Logos Core module manifest.

## What we would NOT do

- Build a new LLM. The agent uses whichever model the owner picks.
- Solve LLM inference on LEZ (that is a separate, much harder prize). The model runs off-chain; only the agent's actions are on-LEZ.
- Build a UI; deliverable is the module + CLI + scenario.

## Operator inputs needed before ship

- Funded LEZ testnet wallet for the deploy demo.
- Confirmed Logos Storage + Logos Messaging APIs are stable enough to depend on.
- One Logos node to deploy the demo agent on.

## Estimated effort

4-6 weeks. Higher than the others because it touches three Logos subsystems (LEZ + Storage + Messaging) and ships a reference scenario.
