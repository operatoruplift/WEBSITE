# LP-0002: Private M-of-N Multisig

**Status**: Not entered. Prize text captured; design notes only.
**Prize URL**: https://ns.com/LP-0002.md
**Fit**: Adjacent infrastructure.

## Prize summary (from Logos Press)

A proof-of-concept public M-of-N multisig exists for LEZ (lez-multisig), but it is architecturally incompatible with shielded (private) accounts. Member accounts must be fresh zero-nonce keypairs claimed by the multisig program, a constraint that private accounts, which are owned by the privacy protocol and increment nonce on every use, cannot satisfy.

This prize is for a **private M-of-N multisig primitive for LEZ**: one where members are private accounts (with normal nonce semantics) rather than fresh keypairs the multisig program owns.

## Why this is hard

- Private accounts on LEZ have **incrementing nonces** every use. A multisig that "owns" the member account would break nonce continuity for any non-multisig use of that account.
- Membership proofs need to be **zk-private**: a verifier should be able to confirm "M of N signed" without learning which M.
- Threshold scheme has to **survive nonce increments** between sign rounds. Each member signing bumps their nonce, but the multisig's notion of "they signed" must still verify.

## What we would build

If entered, the deliverable would be:

1. A LEZ program (Rust + Risc0) implementing the multisig as a state machine over private-account signatures.
2. A zk circuit proving "M of N private accounts signed this payload" without revealing the M.
3. A reference CLI (`lez-private-multisig`) demonstrating create-multisig, propose-tx, sign-tx, execute-tx.
4. Conformance tests against the existing `lez-multisig` test suite (public-account version) so the contract reads as a drop-in shielded variant.

## What we would NOT do

- Build a public version (already exists as `lez-multisig`).
- Build governance UX (separate Logos primitive).
- Ship a UI; the deliverable is the primitive + CLI.

## Operator inputs needed before ship

- Funded LEZ testnet wallet with enough gas for multisig program deploys + ~50 tx for test runs.
- Confirmed Risc0 toolchain version compatible with current LEZ runtime.
- Access to `lez-multisig` upstream so we can port the public test suite.

## Estimated effort

3-4 weeks for one engineer with Risc0 + LEZ experience. We do not currently have that engineer; the operator-side hire/contractor decision is upstream of this prize.
