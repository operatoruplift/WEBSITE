# LP-0013: Token program improvements: authorities

**Status**: Not entered. Prize text captured; design notes only.

**Fit**: Infrastructure piece. Required by LP-0005 for clean threshold attestations.

## Prize summary (from Logos Press)

Practical, production-oriented improvements to the LEZ Token program to support controlled, real-world token issuance. The current example is intentionally minimal; this prize adds a **mint authority model** that enables:

- Variable supply (mint after initial issuance).
- Revocable control (rotate or burn the mint authority).
- Common issuance patterns expected by wallets and applications.

Solana's SPL Token (specifically the authority + freeze model) is called out as a useful reference, but the implementation has to fit LEZ's privacy semantics.

## Submission requirements (from prize)

- Public repository containing:
  - Code changes to the token program.
  - README + design docs (authority model and lifecycle).
  - Tests and example programs/scripts.
- A narrated video walkthrough where the builder explains what they built and why.
- License: MIT or Apache-2.0.

## Why this is hard

- SPL's authority model assumes a public ledger. On LEZ, mint authority transitions must be auditable without revealing who holds the authority at any given time.
- Revocation needs a zk story: prove "the authority was rotated at block X" without revealing the new authority.
- The token program is upstream of every other token use case (LP-0005, governance, payments). Changes here ripple.

## What we would build

1. A revised LEZ Token program with:
   - `MintAuthority` (optional, can be rotated or burned).
   - `FreezeAuthority` (optional, can freeze a specific account).
   - `TransferAuthority` (optional, allows the authority to move tokens between accounts under a defined policy).
2. Lifecycle ops: `RotateAuthority`, `BurnAuthority`, `FreezeAccount`, `ThawAccount`.
3. Tests covering: mint after rotation, mint after burn (should fail), freeze + transfer (should fail), thaw + transfer (should succeed).
4. Reference issuance scripts: "mint 1M of PRO_TOKEN, distribute via airdrop, rotate authority to a multisig, burn the original authority key."
5. A narrated video walking through the design decisions and the test suite.

## What we would NOT do

- Build a wallet UI; the deliverable is the program + scripts + tests.
- Build the multisig that the authority transitions to; that's LP-0002 territory.
- Solve cross-chain token bridging.
